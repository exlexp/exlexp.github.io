# Verified limitations

1. **Tox interoperability still requires an installed-IWA manual run.** The repository pins and compiles c-toxcore v0.2.22 commit `da26052603369045dceb5dfc8c89919b222d0ce0`, supplies a synchronous import ABI over bounded asynchronous Direct Sockets queues, and exposes real profile/friend/message operations. Localhost browser QA verified WASM startup, a real 76-character Tox ID, and savedata generation. A normal tab cannot perform the final public-network qTox exchange because it has no Direct Sockets; follow `INTEROPERABILITY.md` inside a developer-mode IWA before claiming a specific Chrome build interoperable.
2. **Direct Sockets require an installed IWA.** A normal tab can exercise the UI, vault, and XMPP WebSocket path, but raw TCP/UDP constructors are unavailable. There is no gateway fallback.
3. **XMPP provider support varies.** The provider must expose RFC 7395 over `wss://` and offer SCRAM-SHA-256, SCRAM-SHA-1, or TLS-protected PLAIN. Roster, presence, receipts, chat states, XEP-0198 resumption, and explicitly enabled bounded MAM restore are implemented. File transfer, calls, and group chat are not implemented.
4. **OMEMO and OTR are fail-closed extension points, not working E2EE.** Policy selection, device trust state, downgrade prevention, and the isolated OTR worker lifecycle are implemented. No reviewed OMEMO engine or libotr WASM artifact is bundled, so these providers report unavailable. Plaintext means TLS-only for XMPP and always requires explicit policy/confirmation when E2EE was requested.
5. **Notifications require a running app.** No push server exists; closed-app background delivery is not claimed. Message previews are hidden by default.
6. **IWA installation policy changes over Chrome releases.** Verify the current allowlist/unmanaged installation requirements in official Chrome documentation before public release.
7. **Plugin API v1 is intentionally declarative.** It supports installed manifests, explicit permissions, enable/disable, and command contributions. Arbitrary third-party code, network access, message-body access, themes, and protocol providers are not enabled until a separately reviewed Worker sandbox and signed-package format exist.
